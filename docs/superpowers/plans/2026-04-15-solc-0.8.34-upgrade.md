# solc 0.8.34 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unify the entire `synthetix-v3` monorepo on `solc 0.8.34` with `evmVersion: prague`, removing the `Proxy.sol`/`CoreModule.sol` 0.8.17 lock and normalizing pragma directives.

**Architecture:** Bottom-up, layer-by-layer bumps following the Cannon dependency graph. Each task produces a green CI state and is independently revertable. Full proxy redeploy is accepted; no production migration is part of this plan (tracked separately).

**Tech Stack:** Solidity 0.8.34, Hardhat, Cannon, Foundry, Yarn 4 workspaces, `@synthetixio/hardhat-storage` plugin.

**Spec:** [`docs/superpowers/specs/2026-04-15-solc-0.8.34-upgrade-design.md`](../specs/2026-04-15-solc-0.8.34-upgrade-design.md)

## Common Validation Cycle

Referenced from tasks below. Run this whenever a task says "Run validation cycle for `<pkg>`":

1. **Build:**

   ```bash
   yarn workspace <pkg-name> clean
   yarn workspace <pkg-name> build:contracts
   ```

   Expected: build completes, no compiler errors. Warnings about unused vars in generated code are tolerable.

2. **Regenerate + diff storage dump** (only for packages with `storage.dump.json`):

   ```bash
   cd <pkg-dir>
   diff -uw storage.dump.json storage.new.dump.json
   ```

   Expected: **only metadata hash changes** (lines like `"hash": "..."`). Slot-level changes (offsets, types, names) → STOP and investigate before continuing.

3. **Apply new dump to baseline:**

   ```bash
   cp storage.new.dump.json storage.dump.json
   ```

4. **Run tests:**

   ```bash
   yarn workspace <pkg-name> test
   ```

   Expected: all tests pass. New test failures → debug before commit.

5. **Lint:**

   ```bash
   yarn workspace <pkg-name> lint
   ```

6. **Commit** with the message from the task.

## Rollback Strategy

If any task fails the storage-layout gate (slot changes detected):

1. Revert the latest commit: `git revert HEAD --no-edit`
2. Investigate the affected contract — likely an accidental struct field reorder or type width change introduced by compiler optimizer
3. Address the source of the layout change (pin specific contract's compiler via hardhat `overrides` if needed)
4. Re-run the validation cycle

If a later task reveals an issue in an earlier step (e.g., perps-market tests fail due to a core-contracts regression):

1. `git log --oneline` to find the offending commit
2. `git revert <sha> --no-edit` to undo that single task
3. Fix and re-commit as a new task
